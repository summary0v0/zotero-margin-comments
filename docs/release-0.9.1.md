# 0.9.1：修复居中长高亮集中在右侧

旧规则把选区整体中心等于或超过页面中线的批注归入右侧。单栏正文的整行、跨行高亮往往具有相似的左右边界，容易使大量卡片集中到右侧。

## 选侧规则

- 明显靠左、靠右的批注继续就近显示；双栏正文中位于同一栏的高亮不会为凑齐数量被搬到另一侧。
- 文字高亮与下划线的整体宽度达到页面宽度的 40%，且中心距页面中线不超过页面宽度的 5% 时，允许使用任意一侧。
- 先统计确定选侧和已有分配的卡片，再按从上到下的顺序，把新的居中长高亮分到卡片较少的一侧；数量相同时先用左侧。此规则平衡卡片数量，不保证两侧总高度相等。
- 分配按批注和页面旋转方向在本次阅读会话中缓存。修改评论、缩放、筛选、隐藏再显示和新增批注时保留已有选侧；恢复旋转方向时复用该方向的分配。改变选区位置后重新判断，关闭再打开 PDF 时重新分配。
- 独立便签、文字框和图片/区域批注仍按原位置就近选侧。没有评论的纯高亮仍不自动显示卡片。
- 跨行高亮的引线起点改为所选侧真实高亮片段的上边缘，避免落在整体包围框的空白角上。

继续保留 0.9.0 的纸内留白定位、完整卡片宽度、笔记拖选、Markdown / LaTeX 和自动保存。

## 验证入口

- `corepack pnpm test`：算法与 Reader 集成回归，覆盖居中整行/跨行、双栏、缩放、旋转恢复、编辑、新增、筛选和显隐。
- `corepack pnpm run typecheck`、`corepack pnpm run stress`。
- `corepack pnpm run build`、`corepack pnpm run verify:xpi`。
- `node scripts/verify-zotero-runtime.mjs "<zotero.exe>" "<测试 PDF>" --sides`：使用独立配置和独立数据库验证原生 Zotero Reader；结果与截图位于 `build/zotero-sides-qa/`。不控制用户日常 Zotero，也不修改用户文献库。

2026-11-13 验证结果：83 项自动测试、类型检查、50 / 150 / 300 / 600 / 1000 条批注压力测试、构建及 XPI 校验通过。独立 Zotero 10.0.8 在真实 PLLaVA PDF 上完成自动验收：6 条居中文字批注分配为左 4 / 右 2，连同明确选侧与新增批注，页面共 10 张卡片，最终左 5 / 右 5；明确栏位、编辑、50% / 100% / 200% 缩放、隐藏再显示、90 度旋转后恢复和新增批注的稳定性检查均通过。已查看原生截图，确认两侧卡片显示正常。
